# 如果要做成产品：分阶段MVP方案

**状态：方案，未实现。** 本仓库没有音乐网页应用、模型服务、用户账户或云部署。以下验收标准是未来要测试的目标，不是已有功能。

## 产品目标

面向零基础中文用户，用“一个主题 → 四行歌词 → 旋律/节奏 → 自己唱或AI试唱 → 30秒作品”代替复杂DAW首屏。先解决完成小作品的障碍，再扩展专业制作。

## 阶段0：当前研究导航（已完成文档）

交付：19项选型目录、许可边界、入门路线、部署门槛与来源。验收：JSON/CSV一致，内部链接有效，未实测项明示。没有模型效果评测，不把这个阶段称作软件上线。

## 阶段1：浏览器里的原创短循环（未实现）

范围：中文主题卡、可手写四行歌词、4小节节奏网格、有限音阶旋律格、播放/停止、复制段落、音量、项目JSON保存/恢复。

建议技术：TypeScript前端 + Tone.js发声/调度；先使用合成音色，减少第三方采样许可负担。节拍从音频时钟调度，用户首次点击启用AudioContext。数据默认保存在设备，分享前明确告知内容。

暂不做：账户、协作、GPU、声音克隆、自动混音、商店、复杂插件。

验收目标：首次使用者能在引导下完成三个重复有变化的段落；刷新后可恢复；播放不会重复启动多个调度器；保存/导入往返后音符不变；音频导出需单独实现并验证，不把JSON误称WAV。

## 阶段2：录自己的歌（未实现）

范围：麦克风授权说明、试录、波形、按句回听、重录、保留原始take。wavesurfer.js负责显示/回放及Record插件，实际混合/裁剪/渲染由独立音频处理层实现。

工程重点：HTTPS和权限拒绝提示；设备变更；MediaRecorder格式差异；伴奏串音；延迟补偿；采样率与声道转换；音量削顶提示。录音默认留本地，不自动上传。

验收目标：Chrome/Firefox/Safari目标版本分别录制与回放；拒绝权限时仍能作曲；录音不会无提示丢失；导出人声与伴奏同步，无明显削顶。未完成这些测试前不宣传跨浏览器录音稳定。

## 阶段3：可替换的AI试唱适配器（未实现）

首个候选：ACE-Step普通模型；第二候选：HeartMuLa。选择理由是自然语言/歌词入口和已核查许可较明确，不代表已测音质最好。

边界：前端向受控服务提交用户明确选定的歌词/参数；后端采用队列、单任务资源上限、取消与超时、模型版本锁定。每次结果保存输入摘要、model_id、revision、seed、耗时、失败原因及素材权利说明。密钥仅后端管理。

禁止默认加入：权重许可不明的SongGen/SongGeneration；MuLaCover商业输出；未经进一步授权的YuE2企业权重用途或MusicGen商业推理。不能仅按代码LICENSE决定产品模型。

验收目标：明确展示等待/取消/失败状态；显存不足能可控失败；不跨用户泄露录音；记录中文漏字、多字、发音和结构一致性；对不同硬件建立实际基准后才给预计时间。

## 阶段4：可编辑音乐计划（未实现）

方向：和弦选择、旋律钢琴卷帘、MIDI导入导出、按句重生成。YuE2可编辑曲谱仅为研究参考；企业产品接入先解决其权重许可。OpenUTAU/DiffSinger可作为高级离线导出路线，声库授权独立核对。

验收目标：编辑后结果可重现，MIDI与内部工程往返不丢关键信息；重生成对其他段落的影响清晰告知，不承诺未编辑波形完全不变。

## 模块与数据约定（设计草案）

- Project：版本号、标题、BPM、拍号、轨道、音符、歌词段落、素材清单
- Audio asset：来源、许可链接、本地/上传状态、采样率、时长、声道
- Generation job：适配器、模型revision、输入与seed、状态、资源限额、输出引用
- Consent：上传的具体内容与用途、用户确认时间；声音授权与普通麦克风权限分开

应为工程格式定义迁移策略，版本升级不覆盖唯一原件。生成内容有独立保存策略和删除入口；禁止把日志当永久录音仓库。

## 最小测试与上线门槛

- 单元：音符时值转换、节拍位置、工程序列化、调度器释放
- 集成：录音/播放/导出、重采样、取消任务、断线恢复、上传大小和类型限制
- 音乐：中文逐字核对、节奏和句尾、过载削顶、导出时长/声道
- 易用性：让真实新手按路线做一次，记录卡住的步骤；不要用开发者操作成功替代用户测试
- 合规：逐组件许可清单、第三方NOTICE、上传告知、素材授权、声音使用边界
- 成本：用实测每任务GPU秒/内存/存储/重试率估算；当前没有实测，不能给“每首固定几分钱”承诺

下一项最合理的工程工作是阶段1的可点击小循环原型；需要另外明确开发平台、是否只本地运行与发布范围。
